# 로컬 관리자 학습자 검색 설계

## 목적

새 주간 리포트 디자인을 유지하면서 로컬 개발 환경에서 운영 DB의 여러 학습자를 이름으로 찾고, 선택한 학습자의 리포트를 확인한다. 이 기능은 현재의 학습자 본인 인증 흐름을 우회하는 운영 기능이 아니라 로컬 검증 도구다. 배포 환경에서는 완전히 비활성화하며, 추후 교사용 권한 API가 준비되면 검색 UI와 조회 계약을 재사용한다.

## 범위

- 리포트 상단 바깥 영역에 작은 학습자 검색 UI를 추가한다.
- 이름 두 글자부터 검색하며 결과는 최대 10명으로 제한한다.
- 검색 결과는 표시 이름과 숫자 학습자 ID를 함께 보여 동명이인을 구분한다.
- 학습자를 선택하면 선택한 주차를 유지한 채 진단 리포트와 발화 근거를 다시 조회한다.
- 프런트엔드는 운영 DB에 직접 연결하지 않는다.
- 학습자 검색과 타 학습자 리포트 조회는 로컬 전용 서버 경로로만 제공한다.
- 일반 학습자용 API와 기존 본인 인증 동작은 변경하지 않는다.
- 교사 계정, 담당 학습자 관계, 운영 관리자 화면은 이번 범위에 포함하지 않는다.

## 구조

### 프런트엔드

`ReportDashboard`가 선택된 학습자 ID를 로컬 관리자 조회 상태로 관리한다. 별도의 `LocalLearnerSearch` 컴포넌트가 검색어, 로딩, 결과 목록, 선택 상태만 담당한다. 기존 `NumericReportPreview`는 전달받은 진단 리포트를 그대로 그리므로 학습자 검색 책임을 갖지 않는다.

브라우저는 서버 전용 Next 경로만 호출한다. 검색과 관리자 리포트 요청에는 운영 DB 주소나 관리자 키가 노출되지 않는다. 로컬 관리자 기능이 꺼져 있으면 검색 UI 자체를 렌더링하지 않는다.

### Next 서버 경계

Next 서버에 로컬 관리자 전용 프록시 경로를 둔다. 이 경로는 다음 조건을 모두 만족할 때만 요청을 전달한다.

- `ENABLE_LOCAL_REPORT_ADMIN=true`
- 실행 환경이 production이 아님
- 로컬 관리자 공유 키가 설정됨

프록시는 브라우저가 보낸 관리자 키를 신뢰하지 않고 서버 환경변수의 키를 Spring 백엔드에 추가한다. 대상 백엔드는 `http://127.0.0.1` 또는 `http://localhost`만 허용한다.

### Spring 백엔드

로컬 관리자 컨트롤러는 별도 설정 플래그가 켜진 경우에만 생성한다. 일반 `/v1/reports/diagnostic` 경로에는 학습자 ID 재정의 기능을 추가하지 않는다.

로컬 전용 계약은 다음 세 가지다.

- `GET /v1/local-report-admin/learners?query={name}&limit=10`
- `GET /v1/local-report-admin/learners/{learnerId}/diagnostic?week_start={monday}`
- `GET /v1/local-report-admin/learners/{learnerId}/speech-evidence?domain_id={domainId}&week_start={monday}`

모든 경로는 공유 키를 확인하고, 검색어를 정규화하며, 최대 결과 수를 서버에서 다시 제한한다. 검색 결과는 `learner_id`와 `display_name`만 반환한다. 로그인 ID, 연구 코드, 비밀번호 관련 값은 반환하지 않는다.

진단 리포트 생성은 기존 `DiagnosticReportService.current(learnerId, weekStart)`와 `speechEvidence(learnerId, domainId, weekStart)`를 재사용한다. 따라서 계산 규칙과 개인정보 동의 판단은 기존 경로와 동일하다.

### Mormi-AI

새로운 공개 경로를 추가하지 않는다. Spring 백엔드가 기존 내부 리포트 근거 API를 호출한다. 발화 암호화 키가 없거나 올바르지 않으면 실제 발화 문장은 누락하지만, 표현 단계·도움 단계·검증 결과 같은 비민감 구조화 근거는 유지한다.

## 데이터 흐름

1. 사용자가 리포트 상단에서 이름 두 글자 이상을 입력한다.
2. 검색 컴포넌트가 짧은 지연 후 최신 요청만 Next 로컬 관리자 프록시에 보낸다.
3. Next 서버가 로컬 기능 플래그와 대상 주소를 확인하고 공유 키를 추가한다.
4. Spring 백엔드가 이름 부분 일치로 최대 10명을 조회한다.
5. 사용자가 결과 한 명을 선택하면 학습자 ID와 현재 선택 주차로 진단 리포트를 요청한다.
6. 단원을 선택하거나 발화 상세를 펼치면 같은 학습자 ID로 발화 근거를 요청한다.
7. 다른 학습자를 선택하면 이전 학습자의 발화 캐시와 진행 중 요청을 폐기한다.

## 화면 동작

- 검색 UI는 주차 선택기와 리포트 종이 영역보다 위쪽에 작게 배치한다.
- 검색 전에는 현재 보고 있는 학습자 이름을 버튼형 요약으로 표시한다.
- 결과 목록은 키보드로 이동하고 선택할 수 있으며 바깥을 누르면 닫힌다.
- 선택 직후 기존 리포트는 흐리게 남기지 않고 로딩 상태로 전환해 서로 다른 학습자 데이터가 섞이지 않게 한다.
- 검색 결과가 없으면 `일치하는 학습자가 없습니다`를 표시한다.
- 관리자 기능이 꺼졌거나 403을 받으면 검색 UI를 숨기고 일반 본인 리포트 동작을 유지한다.

## 보안

- 로컬 관리자 경로는 production 빌드에서 활성화할 수 없다.
- 관리자 공유 키는 브라우저 번들, URL, 로그에 포함하지 않는다.
- 운영 DB 비밀번호와 발화 암호화 키는 Git에서 제외된 로컬 환경 파일에만 둔다.
- 프런트엔드가 DB에 직접 접속하지 않는다.
- 서버 응답과 로그에 로그인 ID, 비밀번호 해시, 연구 코드, 원문 발화를 불필요하게 기록하지 않는다.
- 운영 DB 연결은 읽기 중심으로 사용하며 이번 기능은 데이터 생성·수정·삭제 API를 제공하지 않는다.

## 오류 처리

- 검색어가 두 글자 미만이면 네트워크 요청을 보내지 않는다.
- 빠르게 검색어가 바뀌면 이전 요청을 취소하고 최신 결과만 반영한다.
- 선택한 학습자가 없어졌으면 선택을 해제하고 안내한다.
- 진단 리포트 일부 근거가 없으면 기존 `기록 없음` 표현을 사용하며 예시값을 만들지 않는다.
- 실제 발화 복호화가 불가능해도 사다리와 검증 결과 조회는 계속한다.

## 테스트

- 검색어 두 글자 제한, 요청 취소, 최대 10개 결과, 동명이인 표기를 프런트 테스트로 검증한다.
- 학습자 변경 시 진단·발화 요청에 동일한 학습자 ID와 주차가 사용되는지 검증한다.
- 관리자 기능 비활성화, production 환경, 공유 키 누락 및 불일치를 Next와 Spring 테스트로 검증한다.
- Spring 검색 결과가 허용된 두 필드만 포함하는지 검증한다.
- 기존 본인 리포트 경로가 학습자 ID 재정의를 허용하지 않는지 회귀 테스트한다.
- 암호화 키가 없을 때 실제 문장만 누락되고 구조화 근거가 유지되는지 AI 테스트로 검증한다.

## 배포 전환

교사용 기능으로 전환할 때 `LocalLearnerSearch`의 조회 인터페이스는 유지한다. Next 로컬 프록시와 Spring 로컬 관리자 경로를 제거하고, 교사 인증 및 담당 학습자 권한을 적용한 운영 검색·리포트 API로 교체한다. 화면 컴포넌트와 선택 상태는 재사용하되 서버의 권한 검사는 운영 요구사항에 맞게 새로 구현한다.
